Mis conclusiones:

La arquitectura de microservicios con Maven, Java y Spring Boot ofrece una combinación que permite que los desarrolladores puedan tener sistemas escalables y con componentes (llamados servicios) pequeños, independientes y que son responsables de su propio despliegue. Estos componentes proporcionan servicios al resto de los componentes en el sistema y también consumen servicios del resto.

El aspecto que más relevancia y utilidad le da a esta arquitectura es la separación de responsabilidades, ya que cada servicio está destinado para una única funcionalidad, evitando así tener una única aplicación con una gran cantidad de archivos para cumplir con todos los requisitos de la aplicación. Además, una arquitectura de microservicios contribuye al manejo de errores en una aplicación, ya que el fallo de un servicio no debería detener por completo a la aplicación. Spring Boot simplifica drásticamente la creación de microservicios listos para producción con su convención sobre configuración, mientras que Java proporciona una plataforma robusta y de alto rendimiento, y Maven gestiona las dependencias y el ciclo de vida de la construcción del proyecto de manera estandarizada y eficiente. En el desarrollo de una aplicación, la utilidad clave es la agilidad: permite a los equipos trabajar en paralelo en diferentes servicios, usar las mejores tecnologías para cada tarea y realizar despliegues más rápidos y menos arriesgados. Para el proyecto del semestre, se podría aprovechar el concepto de separación de responsabilidades al dividr la aplicación en módulos funcionales claros y que cada integrante desarrolle un microservicio independiente de Spring Boot, utilizando Maven para manejar sus dependencias y asegurando que se comuniquen a través de APIs bien definidas (como REST o gRPC), lo que garantizará un sistema modular, mantenible y escalable.
